1. Briefly summarize your client, Artemis Financial, and its software requirements. Who was the client? What issue did the company want you to address?

Artemis Financial was a financial consulting company that wanted to improve the security of its software application. The company needed to protect sensitive financial information and ensure that data transmitted between the application and its users remained secure. My responsibility was to identify potential security vulnerabilities and refactor the existing Java application to implement secure communications and data integrity verification. This involved generating a self-signed certificate, configuring HTTPS, and implementing a cryptographic hashing algorithm to produce a checksum.

2. What did you do well when you found your client's software security vulnerabilities? Why is it important to code securely? What value does software security add to a company's overall well-being?

I think I did well identifying the distinction between vulnerabilities in the existing dependencies and potential vulnerabilities introduced through my own changes. Using OWASP Dependency-Check helped me identify known vulnerabilities in several outdated libraries, including Spring Boot, Spring Framework, and Apache Tomcat. Rather than making unnecessary changes to the existing dependencies, I focused on implementing the security improvements required by the client and verifying that they worked correctly. Secure coding is important because vulnerabilities can expose sensitive information, compromise data integrity, or allow unauthorized access to systems. For a financial company, strong software security also helps maintain customer trust, protect its reputation, and reduce the financial and operational consequences of security incidents.

3. Which part of the vulnerability assessment was challenging or helpful to you?

The most challenging part of the vulnerability assessment was configuring OWASP Dependency-Check to complete its scan successfully. The original project used an outdated version of the plugin, so I updated it to version 13.0.0. My initial scan encountered an error because the NVD API key was missing, preventing the tool from updating its vulnerability database. After correcting the configuration, I was able to complete the scan and generate the vulnerability report. This process was helpful because it reinforced the importance of understanding the tools being used rather than simply following instructions. It also demonstrated how vulnerabilities can exist in third-party dependencies even when the application code itself appears to function correctly.

4. How did you increase layers of security? In the future, what would you use to assess vulnerabilities and decide which mitigation techniques to use?

I increased the application's layers of security by implementing SHA-256 hashing for data integrity verification and enabling HTTPS to protect information transmitted between the client and server. I generated a self-signed certificate using Java Keytool with a 3072-bit RSA key and configured the application to use TLS on port 8443. These measures provide different types of protection, demonstrating a defense-in-depth approach rather than relying on a single security feature. In future projects, I would continue using tools such as OWASP Dependency-Check to identify known vulnerabilities and combine those results with manual code reviews and functional testing. I would prioritize mitigation techniques based on the severity of each vulnerability, whether the affected functionality is actually used, and the potential impact on the application and its users.

5. How did you make certain the code and software application were functional and secure? After refactoring the code, how did you check to see whether you introduced new vulnerabilities?

After refactoring the application, I tested its functionality by running the Spring Boot application and accessing the checksum endpoint through HTTPS. I verified that the application returned the original data string and its SHA-256 checksum correctly. I also ran Maven's automated tests, which completed successfully with one test executed and no failures or errors. To assess security, I reviewed the modified code and configuration and performed a secondary vulnerability scan using OWASP Dependency-Check. The scan identified known vulnerabilities in the existing third-party dependencies, but I had not added any new application dependencies during the refactoring process. Although this supported my assessment that the changes had not introduced new dependency vulnerabilities, a direct comparison with a baseline scan would be needed to verify that conclusively.

6. What resources, tools, or coding practices did you use that might be helpful in future assignments or tasks?

Several tools and practices from this project will be useful in future software development assignments. Eclipse provided the development environment for modifying and testing the Java application, while Maven helped manage the project dependencies and execute automated tests. Java Keytool allowed me to generate and export a self-signed certificate, and Java's MessageDigest class provided an established implementation of SHA-256 without requiring additional libraries. OWASP Dependency-Check was particularly useful for identifying vulnerabilities in third-party components. I also gained experience troubleshooting configuration problems, reviewing error messages, and verifying application behavior after making changes. These are practices I can apply to future projects regardless of the programming language or development environment.

7. Employers sometimes ask for examples of work that you have successfully completed to show your skills, knowledge, and experience. What might you show future employers from this assignment?

I could use this project to demonstrate my ability to evaluate an existing application, implement security improvements, and verify that those improvements function correctly. The refactored Java code demonstrates my understanding of cryptographic hashing, while the certificate generation and HTTPS configuration show my ability to implement secure communications. I could also provide the OWASP Dependency-Check report and Maven testing results as examples of how I evaluate software quality and security. I think the most valuable aspect of this project to demonstrate to an employer would be the complete process, from identifying security concerns and implementing changes to testing the application and documenting the results. It shows that I understand software security as an ongoing process rather than something that can be addressed through a single feature or test.
